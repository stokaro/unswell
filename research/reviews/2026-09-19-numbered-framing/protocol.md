# Count-centered section framing

This is a bounded regression study for the maintainer's provider guide example.
It evaluates a numerical lead repeated by a heading that names only the count
and a generic content noun. It does not evaluate authorship, count correctness,
or the recall of all editorial defects.

Read the whole development page. Preserve concrete amounts, technical objects,
format requirements, and headings that name their task. Annotate both the lead
and its repeated heading, with a repair that names the configuration topic.
Do not count a finding on the next document-announcement sentence as coverage.

Before implementation, freeze four complete confirmation pages by source
identity: two unused Ptah pages and two unused historical pages. Select from the
previous pinned frame using a fixed metadata ranking, without diagnostics.
Exclude every previously reviewed repository/path, including newer versions of
the same document. Historical dates do not establish human authorship.

The same Codex assistant reads each page and records target-family defects and
controls before diagnostics. The reviewer is not an independent human annotator.
Freeze candidate runtime files before inspecting confirmation outputs. Review
every new finding and every frozen target-family miss afterward. Report the
small sample and unresolved broader forms; no universal precision or recall is
inferred from it. Further tuning after confirmation needs another sample.

The supplied page is exposed development evidence. Synthetic public API and CLI
fixtures test number variation, exact source mapping, paragraph/code/list
boundaries, protected text, explicit requirements, policy, budgets, and errors.
The rule cannot compare the number with YAML field counts or prove that an
unstated quantity is unnecessary. Gate thresholds remain unchanged.
