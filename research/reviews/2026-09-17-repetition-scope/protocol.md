# Repetition scope, issue 300

Use the frozen 26-page full-page audit as development evidence. Keep its labels,
including the glossary paraphrase, unchanged. Compare against merged PR 302 at
6f854b634657f45206221b205fe6abb8b4bb7d6d.

Before implementation, select six confirmation sources by the minimum SHA-256 of
`issue300-confirmation-v1\n` plus the pinned reference URL, one per cohort/length
cell. Cohorts are Ptah and historical; lengths come from the earlier frozen frame.
Exclude all 26 development sources and all nine framing-confirmation sources.
Keep all selected files regardless of their findings. Formats follow selection;
this small sample does not establish performance for every format or repository.

The implementation will bound sentence and opener comparisons by grammar-derived
section/owner context, table cells with independent roles, and explicit leading
conditions that distinguish task variants. It will recognize complete duplicated
short unordered list items within one list and section. Comparison must preserve
case-sensitive identifiers, numbers, negation and issue references, including a
single identifier formatted as inline code. Protected commands, URLs and arbitrary
code must not be flattened into prose. Do not lower the existing sentence minimum,
change gates, add a changelog exclusion or weaken work budgets.

Exact item identity and semantic paraphrase are separate questions. In particular,
the glossary example requires a repeated proposition; sharing words about a map,
page or definition is insufficient. Report any remaining miss explicitly.

After implementation, the same Codex assistant will read all confirmation source
prose before opening diagnostic outputs. Annotate repeated-information defects,
uncertain judgments and useful parallel wording with original UTF-8 ranges and
concrete rationale. Review the full source files; do not expand imports or images.
The maintainer accepts this assistant review under ADR 0041. It is not independent,
blinded or human annotation. Freeze these labels before scanning; do not tune the
matcher from confirmation outcomes.

Publish technical and strict before/after reports, all added and removed diagnostic
dispositions, complete related locations, costs and event-level credit. Count each
annotated event once, only when the actual repeated passages are located. Preserve
uncertain labels without positive credit. Separate targeted repetition recall from
the development audit's broader defect denominator. State losses as well as gains.
No population recall, authorship accuracy or qualified-default claim follows from
this development experiment; default qualification remains a separate decision.
