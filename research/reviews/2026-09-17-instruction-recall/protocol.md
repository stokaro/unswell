# Instruction scaffolding and redundant predicates

This iteration continues #309 from PR #308 at
`f4d6d7f1f784e4691182a394481bf8d6d866fc23`. The objective remains useful
complete-page recall of editorial defects, with false alarms measured. The
working 80% recall / 85% soft-diagnostic precision target is still unmet.
A gain on familiar examples cannot establish that objective.

## Construction hypotheses

Use the 64 previously reviewed pages as exposed development material. Keep their
labels, source bytes and separate annotation scopes unchanged. Define candidates
through clause structure and context; an isolated word does not establish a
wording defect.

1. Instruction scaffolding: an impersonal capability introduction with an
   infinitive technical action and an object, often followed by an anaphoric
   method announcement. The edit states the supported action or method directly.
   Preserve capability or optionality; do not turn a possibility into an
   obligation. Epistemic possibility, possible failures, permission boundaries,
   negation and conditional capability limits are negative controls.
2. Reader-intention prefaces: a wish/want/intention clause introduces the same
   goal that the adjacent instruction implements. A concise purpose clause can
   preserve that goal. Actual input, state, security and failure conditions must
   remain distinct from preferences. A bare reader-directed instruction is not
   itself a defect.
3. Redundant predicates: a subject already names a location/path or reason, and
   its predicate restates that relation without adding an actor or condition.
   Require the grammatical subject and predicate, not just nearby words. Files
   located on disk, error paths in control flow, explanatory reasons and API
   names require close negative controls.
4. Indirect action announcements: a bounded anaphoric method clause delays an
   explicit action using generic doing/performing language. Its context must
   supply the actual goal or method. Preserve reference operands and instructions;
   do not diagnose every passive clause, nominalization or explanatory summary.

These are candidate families, not a promise to support every missed passage.
The indirect Ptah narrative tails and abstract worth announcements in #309 may
require more analysis than these constructions provide. Report unsupported
cases; do not hide them by changing the frozen labels or claiming a length
warning identifies the wording problem.

Reuse the public engine, extraction, source maps, NLP contract, shared features,
window budgets, policy and reporters. New diagnostics must give the actual
source ranges and editing guidance, including related ranges where needed.
Protected code cannot become construction vocabulary. Keep modals, conditions,
negation, quantities, identifiers and technical boundaries intact. Runtime stays
pure Go and offline. No new model calls, classifier percentage or lower gate.
A catalog or feature change requires explicit identity/version updates.
