# #349 fresh source-function acquisition

Date: November 9, 2026. This packet acquires a new, page-disjoint editorial
challenge after the failed lexical source-context screen. It is an exposed,
cue-enriched research sample, not a prevalence estimate, a prospective
confirmation set, or product qualification. No model service call is planned.
The old 36 pages, 123 events, labels, and 80% FULL / 85% accepted gates remain
unchanged.

## Selection before content review

Run exactly these three GitHub code-search queries, requesting the first 30
results sorted by indexed time descending. Save each complete JSON response
before opening a matched file:

1. `"it is worth noting" filename:README.md size:4000..20000`
2. `"powerful and flexible" filename:README.md size:4000..20000`
3. `"the following table" filename:README.md size:4000..20000`

Within each response, select the first three results from distinct public
repositories that are absent from the explicit prior-source exclusion set in
`select.py`. A repository can occur only once in the nine-page packet. Preserve
result rank, repository, path, search blob SHA-1, and the full response hash.
Commit this metadata selection before fetching any file content. Do not
replace a selected source because it lacks a defect, has an inconvenient
control, or challenges the candidate. An unavailable or non-UTF-8 selected
source is recorded as invalid and remains in the acquisition denominator.

For each selected repository, obtain the default branch's exact commit SHA,
then fetch the selected path at that commit. Require the downloaded bytes to
match the search blob SHA-1 using the Git blob header and record SHA-256 of the
original UTF-8. Preserve the complete source page. Do not rely on a rendered
GitHub excerpt or construct a second Markdown parser.

## Source-only review before candidate output

The root Codex assistant reads each complete pinned page before running or
seeing a new candidate. Record every clear source-supported opportunity in
the six #349 purposes: empty framing, wordiness, vague claims, unjustified
intensifiers, needless repetition, and needless complexity. For each, record
an exact original UTF-8 byte span and quote, operator, concrete reader burden,
useful content to retain, and whether a meaning-preserving edit is established.
Separately record at least two cue-bearing controls per valid page when
present: `retain`, `optional`, `out_of_scope`, or `technical_uncertain` with a
reason. An unmarked passage is never assumed clean. The assistant is the
actual reviewer under ADR 0041, not a human annotator.

Seal the source-only labels and source hashes before any candidate is run.
Only then choose and freeze a genuinely new source-function mechanism. The
prior cue selector, bag-of-words source-context admission, and old prompt
cannot be reused with threshold changes on exposed grades. Any candidate
must be evaluated against all valid selected pages, all frozen positives and
controls, every delivered finding, abstentions, source binding, and edit
safety. If this acquisition yields fewer than five clear positives spanning
at least three repositories, report insufficiency and acquire another
preselected packet rather than fitting or claiming transfer.

The nine pages are deliberately enriched for ambiguous editorial cues. Their
positive rate cannot estimate the rate in ordinary documentation. A pilot on
these pages cannot replace the full 123-event development screen or separate
reserved prospective confirmation.
