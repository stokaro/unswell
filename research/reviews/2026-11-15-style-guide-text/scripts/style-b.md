## Tone and content

- Be conversational and friendly without being frivolous. Write as a knowledgeable colleague would explain the subject.
- Write for a global audience. Avoid idioms, slang, jokes, and culture-specific references.
- Avoid buzzwords and jargon. Do not pre-announce: say the thing, not that you are about to say it.
- Do not use "please", "simply", "easy", "easily", "just", or "quickly" for instructions.
- Do not make claims about future features or about how good the product is. Describe what it does.
- Do not use exclamation marks.

## Language and grammar

- Use second person: "you", not "we" or "the user".
- Use active voice. Make clear who or what performs the action.
- Use present tense for behavior.
- Put a condition before the instruction it applies to: "If the build fails, run the command again."
- Use standard American spelling and punctuation. Use the serial comma.
- Keep sentences short. One idea per sentence. Define an abbreviation on first use.
- Use the same word for the same thing throughout.

## Formatting and organization

- Use sentence case for headings. A heading describes its section; it is not a question unless the section answers it.
- Use a numbered list for steps in sequence and a bulleted list for other lists. Introduce a list with a complete sentence.
- Put code-related text in code font. Introduce a code sample with a sentence that ends in a colon.
- Do not use bold for emphasis; use it for user interface elements only. Do not use emoji.
- Link text describes the target. Do not write "click here".
