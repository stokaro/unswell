# #349 repair-first necessity pilot

Status: preregistration, before any response from this packet. This is exposed
development on four previously frozen public source pages, not a new
confirmation cohort or product qualification. The original 123 reference
events, source groups, and reserved prospective pages remain untouched.

## Hypothesis

The last additive generation/admission pilot bound every generated diagnosis
to source, but its separate admission stage admitted all eight candidates and
only four were accepted on complete-source review. None of four frozen events
was FULL. A candidate that must include a concrete minimal revision may make
the editorial necessity and meaning-preservation burden testable before
delivery. This tests an edit-first candidate contract, not another threshold
or phrase rule. A diagnosis is useful only if the proposed change fixes that
specific burden while retaining the page's technical and editorial meaning.

Reuse the four source-disjoint public pages and the four positive events and
four retain controls frozen before the previous model run in
../2026-11-10-additive-admission-pilot/. Their source-only review is already
exposed to the researcher; this experiment does not reset it to blind status.
No prior generated finding, admission judgment, source-only event, or reviewer
grade is included in model requests.

The request contains each complete source and its current-engine eligible unit
inventory: exact raw slices, original UTF-8 byte spans, and eligible segments.
There is no second Markdown parser. For every proposed revision, the response
must name a single unit ordinal, quote a unique contiguous original substring
wholly inside one eligible segment, state the concrete defect, provide a
replacement that is no longer than the quote, and explain which useful meaning
is retained. An empty replacement is an explicit deletion. At most six edits
per page; zero is valid. The binder rejects wrong source hashes, ambiguous
quotes, protected spans, oversized fields, and any changed response shape.
It records original byte offsets. It does not apply edits to source files.

## Execution and failure policy

Before any call, freeze the prompt, response schema, exact four requests,
source and review identities, runner, scorer, model, effort, and limits in
packet/freeze.json and commit the packet. Verify the freeze immediately before
execution. A changed contract requires a new packet, never a repair of this
one. The predeclared category-equivalence rule is: an edit may receive FULL
credit despite a different category name only when the reviewer confirms that
its diagnosis names and its revision fixes the exact frozen source-specific
burden. Shared location alone does not qualify.

Use GPT-6-Astra medium through the existing Codex subscription, one ephemeral
tool-free read-only call per page, sequentially. Maximum four calls, one
attempt per page, ten minutes per call and two hours total. Stop at the first
CLI, trace, schema, binding, source, resource, or timeout error. Never retry or
repair a response under this packet. Preserve raw requests, trace, response,
bound output, and token usage. The user's standing explicit authorization for
necessary model work applies to this bounded run; no paid API route is used.

## Review and decision

The root Codex assistant reviews every proposed edit against the complete
source under ADR 0041; it is not a human annotator. Each edit receives
accepted, uncertain, or rejected necessity and yes, uncertain, or no edit
safety. An unsafe or unresolved edit stays in the delivered denominator.
Review every frozen positive and retain control without relabeling them.
FULL requires an accepted diagnosis and safe supplied edit that addresses the
exact original defect. A category-equivalent case needs an explicit rationale.
A retain-control hit is any proposed edit targeting that control, even if the
edit is later rejected. Duplicates and conflicting proposals remain separate
delivered edits. Report invalid and abstaining pages, FULL/PARTIAL/MISSED
events, accepted fraction, all safety outcomes, and control hits separately.

Advance this method only if all four pages bind, at least three of four
positive events are FULL, at least 85% of delivered edits are accepted and
safe, and no retain control is hit. Otherwise retire this exact packet. Even
a positive pilot would authorize only a larger independent test: current-main
combined output on all 123 original events still needs at least 80% FULL
recall and 85% accepted actual findings in each complete cohort, complete
edit-safety review, and separate prospective confirmation. No product rule,
default, or origin claim follows from this pilot.
