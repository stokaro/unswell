points to `03845fae652abdbd9588031a374d1a54155aa24c`, the commit that the

## What this release is for

The checker is the same as in alpha.24. The site builds the pages of a
release from its tag, and this release carries three changes of the site.

The latest release is at the root of the site. After the release these
addresses were read in a browser without a window:

| Address | What it gave |
| --- | --- |
| `unswell.dev/` | The front page of this release, with the canonical address `https://unswell.dev/`. The answer holds no redirect. |
| `unswell.dev/getting-started/` | The page itself. It names `v0.1.0-alpha.25` as the published release. |
| `unswell.dev/v0.1.0-alpha.25/getting-started/` | A stub that leads to `unswell.dev/getting-started/`. |
| `unswell.dev/v0.1.0-alpha.24/` | The front page of that release, in its folder. |
| `unswell.dev/edge/` | The front page of the current tree. |
| `unswell.dev/v0.1.0-alpha.12/reports/`, a release that the site no longer builds | The reports page at the root. |

The research report belongs to no version. `unswell.dev/research-report/`
gives the report with no version picker, and its copy inside a release leads
there.

The configuration page has a section that says what the `strict` profile adds
to `technical`. The page at `unswell.dev/configuration/` holds it.

## How the site was deployed

The documentation workflow did not run for the tag. The site that the
addresses above were read from came from the run for the commit that the tag
names: that run listed the tags after the tag was pushed, and it built this
release at the root.

The run that the release workflow asked for built and checked the site and
then failed at its deploy step. The Pages artifact was uploaded, and the
deploy step, which started two seconds later, listed no artifact of the run.
A second attempt of that job failed too, because the run then held two
artifacts of one name. A new run on main failed in the first way. The deploy
job now waits until the listing shows the artifact
([#651](https://github.com/stokaro/unswell/pull/651)). The
[first run with that wait](https://github.com/stokaro/unswell/actions/runs/44624878306)
deployed the site, and its check of the published root found this release
there.
