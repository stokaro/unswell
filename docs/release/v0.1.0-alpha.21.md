and Windows.

## The action checks the whole repository again

Until this release the job of the release workflow checked only the README
and the documentation through the action. The action ran the CLI with its
limit of 30 seconds, and its manifest had lost the declarations of the
`timeout` and `jobs` inputs, which set another limit and the number of
workers ([#535](https://github.com/stokaro/unswell/issues/535)). The action
declares both again, and the job checks the whole repository with both set.

Before the tag, the action commit named above checked the whole alpha.20 tree
with the alpha.20 archive on the three systems: 1,598 documents each. A
binary built from the commit of this release checked this tree on the same
systems in 11 to 20 seconds.

## The published binary and the pages that the parser changes were measured on

The changes of this release to the Markdown and MDX parser were measured with
builds of their branches, before the release. The binaries from the published
macOS ARM64 archives of alpha.20 and alpha.21 were run again on 6,827
Markdown pages of documentation that the maintainer keeps for measurements,
with the profile `technical`:

| Result | Pages |
| --- | ---: |
| Complete with both binaries, and the same report | 6,790 |
| Complete with both binaries, and another report | 18 |
| Incomplete with alpha.20, complete with alpha.21 | 19 |
| Incomplete with alpha.21 | 0 |

Each of the 18 pages holds a code span with a `<`, which alpha.21 protects.
Their findings are the same on 16. On the other two, which are copies of one
page, `syntax.closing-denial-density` reports once more.

The comparison needs the pages, which stay with the maintainer.
