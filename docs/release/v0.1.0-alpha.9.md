[v0.1.0-alpha.9](https://github.com/stokaro/unswell/releases/tag/v0.1.0-alpha.9)
at `e742b1aff38679174801db66584699ae197fbf96`. The tag is signed and its

## What the release changed, in the published binary

The binary from the published macOS ARM64 archive ran the three commands:

| Command | Result |
| --- | --- |
| `unswell check` on a page that opens with `Sure, here is a summary` | One finding of `scaffold.chat-preamble` on the opener, and the gate fails. Exit code 1. |
| `unswell trim` on one documentation page | Four trims accepted and one proposal rejected by the check, nothing written. Exit code 0. |
| `unswell trim --write` on the same page | The accepted trims written to the file. Exit code 0. |
| `unswell review` on the same page | Nine findings bound to source bytes. Exit code 0. |

The model was `claude-sonnet-5-5`, served by a local assistant program. This
is one page and one run of each command. It shows that the published binary
carries the opener and reaches a model. The measurements are elsewhere:
[ADR 0054](../adr/0054-trim-measured-against-editors.md) for trimming against
human editors, and
[ADR 0055](../adr/0055-phrase-listed-on-editor-reference.md) for the opener.

The test parts of the human-reference record ran with a build of the parser
change that this release ships. No document failed there: 576 of 576 with each
of two models. With the alpha.8 parser, 5 of 277 development documents had
failed with one model.

## Distribution updates

The publishing app created
[Homebrew PR #18](https://github.com/stokaro/homebrew-unswell/pull/18) and
[Action PR #19](https://github.com/stokaro/unswell-action/pull/19). Their checks
passed. Both need a maintainer review before merging. Until then the tap's
formula names alpha.8 and the Action's default names alpha.7; the Action's
update to alpha.8 is still open as its PR #17, which PR #19 replaces. The Action
accepts `version: 0.1.0-alpha.9` explicitly, which is what the release consumers
above used.

## Docker Hub

The mirror holds releases up to alpha.4. Renew the Docker Hub token in the
repository secrets, then run the `Mirror containers to Docker Hub` workflow for
`0.1.0-alpha.6`, `0.1.0-alpha.7`, `0.1.0-alpha.8`, and `0.1.0-alpha.9`. The
weekly `Release prerequisites` workflow logs in with the same credential and
fails while it is rejected.

## Scope

Scan cost was not measured again for this release. This evidence does not
qualify rule precision; the
[qualification record](../research/rule-qualification.md) reports that with
assistant reviewers, and the
[human-reference record](../../research/reviews/2026-11-12-human-reference/README.md)
reports what was measured against people. Final race, fuzzing, and coverage
checks remain deferred under their existing roadmap decisions.
